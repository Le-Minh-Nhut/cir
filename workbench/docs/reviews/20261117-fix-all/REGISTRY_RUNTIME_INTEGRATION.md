## Models API cache freshness

`GET /api/models` stamps `WORKBENCH_RUNTIME_ADAPTATION` and operator env file identity, so same-process process-selector changes or file replacement/change invalidate cached response. `model_settings.file_settings()` keeps one bounded LRU entry keyed by operator-env path and stat identity; updates are reread without a cache alias or process-environment mutation. Each response reports `selected_runtime_adaptation` from that same setting. Actual autouse-fixture consumer regression warms the endpoint and flips process and file selectors: `workbench/tests/test_api_models_cache_staleness.py::test_models_api_refreshes_runtime_selection_and_operator_file`, 1 passed, 5 warnings in 2.99s, exit 0 using `workbench/envs/ctl312h/bin/python`.

It revalidates every observed member and relevant directory membership before returning; a changed RECORD, metadata file, member, or package entry aborts rather than certifying a mixed snapshot. `_remember()` uses the current verification's validated digest, avoiding the second full pass. The complete filesystem-focused regression file `workbench/tests/test_a32_fingerprint_invalidation.py` passed: 16 passed in 0.48s, exit 0 under exclusive CPU slot A.
