## Source-backed scoring changes

- **AirKnow:** `workbench/third_party/AirKnow/lavis/models/blip2_models/blip2_cir.py:499-526` L2-normalizes query and each of 32 target-token features. `test_BLIP2.py:134-144` uses raw max-token dot product; normalization lines are commented out. Adapter keeps this source-evaluator scoring expression and preserves singleton query/gallery axes rather than source's `squeeze()`. Source evaluator separately excludes FashionIQ source rows at `test_BLIP2.py:147-151`; CIRCUS's full-gallery score does not mask reference rows, so adapter eligibility describes the CIRCUS score rather than the FashionIQ evaluator protocol.
- **CLIP4Cir:** `workbench/third_party/CLIP4Cir/src/validate.py:41-45,97-107` normalizes query/gallery, scores cosine (distance `1 - dot`). `torch.nn.functional.normalize` defaults `eps=1e-12`; `workbench/composition/model_clip4cir.py` now uses that exact epsilon for query and gallery normalization instead of float32 `tiny`, which disagreed for near-zero features. Both registry wrappers use this same implementation.
- **DCNet:** `workbench/third_party/DCNet/trainer/trainer_joint.py:188-218,239-240` computes composition and query-conditioned correction, then fuses `log_softmax(score_comp, dim=-1) + log_softmax(score_corr, dim=-1)` over the entire gallery. Adapter packs native source/text/composed/gallery experts in versioned `dcnet-context-v1` layout and calls upstream `get_correction`/`get_score_matrix` in a persistent model worker. It builds full-gallery scalar composition/correction matrices in bounded target chunks, then applies native full-gallery `F.log_softmax` once to each matrix and sums in native order. `workbench/third_party/DCNet/model/composition.py:176-204` confirms per-pair `FusDiff`; latent correction stays chunked. Native FashionIQ masks reference outside scorer; CIRCUS full-gallery path keeps it.
