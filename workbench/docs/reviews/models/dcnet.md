CRITICAL FINDINGS —

1. **P1 — the declared resize recipe cannot produce the required `resized_images/` from this dataset.** Observed (`_run_resize` exec probe): `resize input missing: /tmp/dcnet_probe/root2/images/B009PMCJLW.jpg (and 15535 more)`; cause `workbench/scripts/prepare_model.py:443-450` only tries `{id}{ext}` and `{id}.jpg`, while the shipped canonical distribution is 74,381 PNGs and zero JPGs (`data/FashionIQ/images`, `data/fashionIQ_dataset/images`) and the same is true under either candidate root (`data/FashionIQ` is what `WORKBENCH_FASHIONIQ_ROOT`-style default resolves to: `resolve_config().FASHIONIQ_ROOT = /home/heheboiz/data/cir/data/fashionIQ_dataset`). Consequence: the one generated artifact the contract marks automatable is silently un-runnable; `dry_run` reports full coverage (`[OK] dry-run: dcnet would resize 3817 …`) because it never stats sources (`:434-437`), so an operator sees green. Recommended action: fix the identifier→source resolution to search the declared extension list (or add `.png` to the recipe's source probing and keep `.jpg` output), and make `dry_run` fail when zero source files exist. Do not "fix" this by writing `fashioniq_image_extensions: [".png"]` — the evaluator's path is `candidate_id + '.jpg'` (`data_loader/CE_dataset.py:72`), so PNG output would break the load instead.
2. **P1 — GloVe val PKLs are non-reproducible and their declared generator never consults the workbench root.** `preprocess/process_cap.py:31` `np.random.normal(0, 0.3, (300,))` with no seed anywhere in the file (`grep` shows seeding only at `test.py:105-112`, `train.py:18-29`), and the script reads/writes `'../dataset/fashioniq/captions'` (`:13,35,40`) relative to `preprocess/`. Recommended action: keep `AUTHOR_ARTIFACT_PREFERRED`; add an explicit "author PKLs must be staged at `<checkout>/dataset/fashioniq/captions/`" note plus that path in the contract's `paths`, and refuse regeneration without a recorded seed and hashes.
3. **P1 — the declared protocol is an inference, not a paper claim.** The paper states no candidate/reference rule, and the benchmark owner's paper/README states none either; `fashioniq_full_gallery_ref_excluded` + `literature_split_label: original` rest on reading `trainer_joint.py:216-218`'s `-10e10` mask.
