## CRITICAL FINDINGS

1. **P0 — the pinned evaluator can never be entered: `test.py` is not an executable, and the trainer that would drive it is also broken.** `test.py:6` defines `test(params, model, testset, category)` and nothing else executable: no `ArgumentParser`, no `__main__`, no argv access, and no importer anywhere in the tree. `train.py:128-154` is the only `__main__`, and it ends at `create_model_and_optimizer()` with no train or eval loop, so the documented entrypoint cannot reach `test(...)` at all. Registry records this only indirectly (`reproduction_status: BLOCKED_CHECKPOINT_MAPPING_UNVERIFIED`; no `command_status` field at all — observed `'command_status' in model` -> `False`, unlike `clvc_net`/`dcnet`/`sprc`/`tgcir`/`limn`). Action: record `command_status: COMMAND_BLOCKED_SOURCE_ENTRYPOINT` on `pair` so the reader is not told a mapping problem is the *only* blocker; never invent a `test.py` CLI.
2. **P0 — `MHTransformer_rev` is absent from the pinned checkout, while `models/model.py:13` imports it unguarded and `:47` instantiates it.** A file named `models/MHTransformer.py` exists; no `_rev` module exists in the tree, in `git ls-files`, or anywhere on the filesystem (`find / -xdev -name "MHTransformer_rev*"` empty; `python3 -c "import MHTransformer_rev"` -> `ModuleNotFoundError`). Every execution path that needs the model dies at import, before any dataset read. Registry and docs already state this (`docs/AUXILIARY_ASSET_AUDIT.md:69`, `docs/PC_TRANSFER_CHECKLIST.md:55`), and it is source-provable. Action: keep BLOCKED; obtain the module from the author or the Drive archive, never synthesise it.
3. **P0 — the checkpoint mapping is genuinely unresolvable, and *both* variants must stay registered.** Independently reproduced: no name reference in the pinned tree (0 grep hits), no download/config section in the README, `save_ckpt` defined and never called, no history in the shallow clone. The author HF repo (`iLearn-Lab/ICASSP25-PAIR`) supplies obtainability (real `resolve/main` URLs, sizes, LFS etags) but its card and the upload commit's 31-byte README assign no dataset to either file, so obtainability does not become identity. Action: keep both `UNVERIFIED`; if the mapping is ever resolved it must come from the author, and the two blobs then map to *whatever* they map to — do not infer from `B1`/`B2`.
4. **P1 — the registry's `fashioniq_ilearn_resized` layout under-checks the fresh constructor.** `data/datasets.py:34-48` runs `train_init_process()` on a cache miss, which reads `captions/cap.{cat}.train.json` (`:63`) for all three categories before validation data; `ilearn_resized_paths` (`fashioniq_layout.py:25-34`) lists only val captions/splits, the correction dicts and `resized_image/`. Action: either add the three train blobs to this layout or declare the constructor's cache (`fashion_iq_data.json` + 6 PKLs, `:37-48`) as a preparation artefact, and say which is contract.
5. **P1 — the required open_clip binary has no provenance and is not registered for `pair`.** `models/model.py:37-38`, `train.py:65-66`, `cirr_test_submission.py:92-93` all resolve `os.path.join('.', 'open_clip_pytorch_model.bin')`, i.e. cwd-dependent; `auxiliary_assets_for_model('pair')` returns `[]` (observed), so nothing validates or fetches it, and `registry/audits/cluster_a_encoder_split.yaml:365-379` records `expected_sha256: null`, `expected_size_bytes: null`. Action: register it (laion2B-s34B-b79K is the audit's declared family) or mark it operator-supplied-unverified, and pin the open_clip version (registry `packages: []`).
6. **P1 — no metric parser for `pair`.** Observed `extract_aggregate_metrics('pair', ...)` -> `AGGREGATE_PARSER_UNAVAILABLE`.
