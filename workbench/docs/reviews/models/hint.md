I did not inspect the actual `split.*.val.json` files (not present in `data/fashioniq_dataset/image_splits/` for the resized layout), so this remains UNKNOWN for the real files, but it is a property of the data, not of either implementation.

Workbench reference handling — `recall_at_k_reference_excluded` (`src/evaluation/fashioniq.py:37-73`):

i.e. sort first, then **remove** the reference column before the top-k hit test. `fashioniq_encoder_recall_at_k` (`src/evaluation/fashioniq_encoder.py:44-47`) uses the same remove-after-sort form, with `stable=True` (`:44`).

Cohort verdict: the candidate universe is identical (ordered first-seen reference-then-target union) and the reference is unretrievable in both. The **procedure** differs: source masks to `-10e10` pre-sort; workbench removes the column post-sort. The two agree on the top-k hit test whenever every other score exceeds `-10e10`, which the workbench doc states as its own justification (`src/evaluation/fashioniq.py:44-52` docstring, and `workbench/docs/FASHIONIQ_PROTOCOL_PARITY.md`, bullet 2). That condition holds for any finite cosine-logit; the source's own single-precision dot products cannot underflow a normalized product to below `-1e10`. So this is a NOT-IDENTICAL-BUT-EQUIVALENT construction, and the workbench is honest about it rather than claiming numeric identity.

2. **`np.argsort(-sims)` is not stable**, and the source truncates to 50 (`test.py:86,100`). `torch.argsort(..., stable=True)` in `fashioniq_encoder_recall_at_k` (`fashioniq_encoder.py:44`) is a different tie rule from the source's. `_assert_comparable` calls ties "an ambiguity … not a property the workbench can pin" (`src/evaluation/fashioniq.py:145-150`). Honest, but it means tied scores can produce different ranks between source and workbench. Severity P3 (ties are unlikely on 512-d normalized features but not impossible).
3. **Category loop.** Source evaluates `['dress','shirt','toptee']` per category (`train.py:198`) and selects the best epoch by the **sum of the three categories' R@10** (`train.py:201`, `current_score = current_score + t[1][1]`). The workbench `macro_average_fashioniq` computes an arithmetic mean and `mean_recall = (R@10 + R@50)/2` (`src/evaluation/fashioniq.py:224-241`). No iLearn source publishes that mean; the registry's `reported_mean: 68.21` must therefore be treated as a workbench aggregate of source per-category numbers (per `workbench/docs/FASHIONIQ_PROTOCOL_PARITY.md`, finding 4). See PAPER-METRIC STATUS.

## METRIC CONTRACT

Source (`test.py:86-107`):

- `nn_result = [np.argsort(-sims[i, :])[:50] …]` (`:86`, `:100`).
- `for k in [1, 10, 50]: r += 1 if test_targets_id.index(test_queries[i]['target_img_id']) in nns[:k]` (`:101-105`).
- `r = 100 * r / len(nn_result)` (`:106`) — denominator is the **query count** (number of validation annotations), as the workbench requires (`src/evaluation/fashioniq.py:31`, docstring `:143`: "The denominator is always the query count").
- Returns `[('{name}_r{k}', r), …]` for k ∈ {1,10,50} (`:107`) — per-category only; no macro, no mean.
- Note: R@50 is computed from a top-50 truncation of a gallery that may be smaller than 50 in principle; the source does not guard this. `_assert_comparable` refuses `k > gallery_count` (`src/evaluation/fashioniq.py:149`). Stricter, not different on a well-formed val split.

CIRR branch for contrast (`test.py:150-156`) divides by `model.temp` (`sims = sims / temp_numpy`) — the FashionIQ branch does **not** (`test.py:74`). This matters for anyone tempted to reuse the CIRR evaluator: `torch.nn.functional`/temperature is applied only in `test_cirr_valset`. Recorded, not a defect in the FashionIQ path.

Workbench (`src/evaluation/fashioniq_encoder.py:31-52`, `evaluate_fashioniq_encoder_category:57-66`):

- `FASHIONIQ_ENCODER_RECALL_KS = (1, 10, 50)` (`:19`) — the same k set.
- `100.0 * sum(hits) / len(hits)` (`:52`) — the same percent scaling and query-count denominator.
- Gallery uniqueness asserted (`:37`), target/reference membership asserted (`:43-44`).

So metric *shape* (percent R@1/R@10/R@50 on a query-count denominator) matches. The *score* does not: HINT's similarity is a max over the target Q-former token axis of a `(Q, D) × (D, T)` product of a 32-token composed query against a 32-token target multivector (`HINT.py:405-434` compose, `HINT.py:436-461` target, `test.py:74-76` matmul + `.max(-1)`), whereas the workbench encoder evaluator takes `model.retrieve(...)` scores against cached gallery tokens (`src/evaluation/fashioniq_encoder.py:127-137`). No claim of score parity is made by the workbench, and none can be made from static reading. UNKNOWN (score identity). STATIC_AUDIT.
