## 3. Gate G3: Mobile Timeout Classification & Decisive Numbers

### Classification
`CONFIRMED_PLAYWRIGHT_HARNESS_DEFECT`

### Decisive Evidence Summary
1. **Frontend Request Behavior in Real Browser**:
   - The React frontend (`App.tsx`) issues **exactly one** `/api/models` request on application mount across all viewports (desktop `1440x900`: 1 request; mobile `390x844`: 1 request; mobile `360x800`: 1 request).
   - In both Scenario 4 (mobile context after desktop) and Scenario 5 (fresh isolated mobile context), `models_requests_count` was measured as **1**. No duplicate, racing, or overlapping frontend requests were generated by the browser.
2. **Root Cause of the Mobile Timeout**:
   - The hypothesis that "mobile startup triggers overlapping `/api/models` requests" was an artifact of the test harness structure in `workbench/frontend/tests/ui_smoke.py`.
   - In desktop testing (`session_cold`, `ui_smoke.py:306-313`), the harness waited for DOM settlement (`/^17 registered models$/`) before executing its out-of-band Python validation request: `models = api_json(base_url, "/api/models")`.
   - In mobile testing (`session_mobile`, `ui_smoke.py:597-600`), the harness waited only for `/api/runs` (`wait_for_runs_loaded`, taking ~10ms), and then **immediately** fired a second out-of-band `/api/models` call via Python `urllib.request.urlopen` while the browser's own cold `/api/models` request was still in flight (taking ~19.3–20.4s).
   - The second concurrent request was entirely synthetic test-induced contention created by the test script, not a browser navigation bug.
3. **Playwright Launch Bug (`A40-UI-01`)**:
   - `ui_smoke.py:662` hardcoded `playwright.chromium.launch()` with zero arguments, which threw `Executable doesn't exist` whenever Playwright browser binaries were absent. Fixed by specifying system Chrome (`channel="chrome"` or `WORKBENCH_CHROME_PATH`).
