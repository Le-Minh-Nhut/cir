## 2. Native aggregate provenance rules (verified, not assumed)

1. **A macro is the unweighted mean of the three category values.** `third_party/CLIP4Cir/src/validate.py:5` `from statistics import mean`, `:281-297` appends one value per category, `:308-309` prints `average recall10/50 = mean(list)`. Same rule in the workbench parser (`backend/metrics_extraction.py:1073-1075`). A pooled recomputation is a **different quantity** (`clip4cir` pooled R@10 = `43.76662307359437`, not `43.8016931215922`).
2. **A served number is one an artifact backs** (`native_measurements.py` `_backed_by_artifact`). A roll-up's own cell is kept as `raw_metrics` and auditable, never merged into `metrics`.
3. **Two roll-ups carry numbers no artifact backs.** `clip4cir_parsed.json`'s `dress_r10 39.11750018596649` and `toptee_r50 71.23916149139404` occur in no other file under `workbench/`; the `43.81821850935618` macro is built from them.
4. **Identity, not proximity, decides a replacement.** `_identity_matches` compares `model_id`/`protocol_id` (+ `checkpoint_id` when the report states one). `clip4cir_rn50x4_fullft` joins its replay only via `identity_join: single_candidate_protocol_unknown` — the row states no protocol, the model has exactly one candidate report, and the checkpoint statement does not contradict. Recorded, not silent.
5. **An artifact with no `replay_type` is neither a row nor a backing report.** That is why `raw/native/encoder.json` and `raw/native/tme.json` (both aggregate-bearing) are served nowhere while `clip4cir_fullft.json`, `conesep.json`, `dcnet.json`, `habit.json`, `hint.json`, `intent.json` (all with `replay_type`) are.
