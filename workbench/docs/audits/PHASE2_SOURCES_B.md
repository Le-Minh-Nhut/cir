# Phase 2 source audit — Sources B

Audit boundary: source inspection only; no checkpoint, model environment, or GPU-PC evaluation was run. Source pins below are the authoritative pinned checkouts in `workbench/third_party/`. `EXACT_MATCH` is intentionally unused: workbench adapters mostly route to upstream evaluators, but routed execution and artifact parity have not been reproduced.

Comparison table columns follow shared schema. `mismatch_severity` uses P0 protocol invalidity, P1 high benchmark impact, P2 reproducibility/provenance, P3 documentation/metadata; `—` means no confirmed mismatch for that row. `conf/protocol/` contains no protocol YAML files in this checkout; model protocol declarations are in `workbench/registry/models.yaml`, interpreted by `workbench/backend/registry.py:load_registry`.

## CLVC-Net (`clvc_net`)

- **Source URL and pinned SHA:** https://github.com/iLearn-Lab/SIGIR21-CLVC-Net/tree/bd9b6889489806cb60676597880f91d918b279cb — `bd9b6889489806cb60676597880f91d918b279cb` (`workbench/registry/models.yaml`, `clvc_net.upstream_commit_sha`).
- **Official dataset entrypoint:** `workbench/third_party/CLVCNet/datasets.py:FashionIQ.__init__`, `FashionIQ.__getitem__`, `FashionIQ.get_test_queries`, `FashionIQ.get_test_targets`. Constructor reads `captions/cap.{category}.{split}.json` and `image_splits/split.{category}.{split}.json`; image files are under `<fashioniq_path>/resized_image/<category>/<id>.jpg`. Each annotation retains its reference (`candidate`), target, and two captions. `FashionIQ.get_test_queries` associates IDs by `self.images.index`; `get_test_targets` defaults `gallery_all=False` and builds first-seen ordered reference/target endpoint union. `train.py:load_dataset` chooses a single category via `--name`; README's three FashionIQ commands train `dress`, `shirt`, and `toptee` separately.
- **Official preparation functions:** no FashionIQ resize/preprocessing script is in pinned CLVCNet. `README.md` instructs resizing with the external FashionIQ `start_kit/resize_images.py`; `datasets.py:FashionIQ.__init__` assumes its `resized_image` output exists. Training/evaluation dataset objects are created by `train.py:load_dataset`. This is not evidence for a specific local resize implementation beyond README's reference.
- **Official text preprocessing:** `datasets.py:FashionIQ.concat_text` builds `"<BOS> {cap1} <AND> {cap2} <EOS>"`. `text_model.py:SimpleVocab.tokenize_text` ASCII-encodes/ignores non-ASCII, removes `string.punctuation`, lowercases, strips, whitespace-splits; `encode_text` maps missing terms to ID 0. `train.py` builds each model's vocabulary from `trainset.get_all_texts()`, which returns the two raw captions separately (`datasets.py:FashionIQ.get_all_texts`), while inference passes the marker-wrapped pair from `get_test_queries`. Consequently marker words are not supplied by that vocabulary source and encode through the unknown-ID fallback unless otherwise present. No correction dictionary is loaded by CLVCNet FashionIQ.
- **Official image preprocessing:** `train.py:load_dataset` evaluation transform is `Resize(256)`, `CenterCrop(224)`, `ToTensor`, ImageNet mean/std normalization; `datasets.py:FashionIQ.get_img` opens RGB images from `resized_image/<category>`. Training uses `Resize(256)`, random crop and horizontal flip. Both local/global branches initialize `resnet.resnet50(pretrained=True)` in `model.py:img_backbone.__init__`; this is a runtime ImageNet weight dependency. The README's external pre-resizing plus source `Resize(256)` is the actual chain; no CLIP transform is involved.
**Native evaluation protocol:** `test.py:test` (FashionIQ `else` branch) obtains every query/gallery feature by explicit Python batch accumulation using `params.batch_size`; it does not use a PyTorch `DataLoader` for evaluation. It L2-normalizes each branch and concatenated feature, computes query-gallery dot products, sets the query's reference slot to `-10e10`, sorts descending, and computes per-category R@1/R@10/R@50. For FashionIQ the query output is concatenated normalized local/global composed features; gallery features are concatenated normalized local/global image features (`test.py:test`; `model.py:compose_local.compose_img_text`, `compose_global.compose_img_text`). `train.py:train_and_evaluate` evaluates the three names separately; it does not define a macro-recall helper. `test.py` has no CLI `main`, model construction, or checkpoint loader; README's bare `python test.py` is not a checkpoint-replay entrypoint.
- **Gallery construction:** `FashionIQ.get_test_targets` uses pair-union reference+target IDs in annotation order with first occurrence retained; `test.py:test` excludes each reference before ranking. This is `fashioniq_val_split`, not full validation split.
- **Checkpoint routing:** `train.py:train_and_evaluate` saves two whole-model pickles, `local_model.pt` and `global_model.pt`, in its per-category model directory. README `Usage` issues one training command per category. Pinned source provides no test-time loader for these files. README links a single `CLVCNET.zip`; its file-to-category/local/global association is not established by inspected code. Registry currently has one `author_drive_unresolved` variant, `checkpoint_serialization: whole_model`, and `category_model_policy: shared` (`workbench/registry/models.yaml`).
- **Auxiliary assets:** evaluation needs torchvision ResNet-50 ImageNet pretrained weights (`model.py:img_backbone.__init__`, `pretrained=True`). Workbench preparation contract records published filename prefix `19c8e357`, but not full digest (`workbench/registry/preparation_contracts.yaml`, `clvc_net_fashioniq.external_assets`). Resized category JPEGs are required. No caption correction asset is used by this source.
- **Current workbench implementation:** `workbench/backend/adapters/models.py:CLVCNetAdapter` names `test.py` but inherits `OfficialScriptAdapter.command`, which raises `NotImplementedError`; registry records `BLOCKED_NO_SOURCE_REPLAY`/`COMMAND_BLOCKED_SOURCE_ENTRYPOINT`. `workbench/backend/fashioniq_layout.py:clvc_resized_paths` requires category `resized_image`, train/val annotations and val splits. `workbench/registry/preparation_contracts.yaml` marks start-kit resizing manual. Local dataset `src/datasets/fashioniq.py:FashionIQDataset.__getitem__` defaults to plain `ordered_and` text, not CLVC's marker-wrapped string; it is not invoked by any CLVC adapter. The registry protocol is `fashioniq_val_split`.
- **Verified match:** reference exclusion and endpoint-union gallery semantics match the declared `fashioniq_val_split` (`workbench/registry/models.yaml`; semantics evidenced by `FashionIQ.get_test_targets` and `test.py:test`). This establishes protocol mapping only, not runnable replay.
- **Confirmed mismatch:** source trains separate local/global whole models per category, while workbench registry says `category_model_policy: shared` and records one unresolved checkpoint variant (`workbench/registry/models.yaml`; upstream `train.py:load_dataset`, `train.py:train_and_evaluate`, `README.md`). Treating one pair as covering all categories would risk wrong category checkpoints (P1). Workbench local default caption construction also omits CLVC's BOS/AND/EOS markers and its tokenizer behavior (P1 if substituted for native input). No CLVC adapter command/checkpoint loader exists (incomplete implementation).
- **Unresolved question:** which exact author ZIP members map to each category's local/global whole-model files, and whether any public checkpoint pair covers all three independent categories. Full torchvision weight digest and exact external start-kit resize behavior also remain unverified.
- **Exact PC verification still owed:** obtain author-attested category/local/global file mapping and trusted hashes; stage three category pairs and required ResNet-50 asset; provide source-backed replay entrypoint or reconstruct only after provenance approval; verify isolated Python 3.7.6/PyTorch 1.6.0 plus torchvision/CUDA; execute every category on GPU and compare native per-category recalls to author evidence. No GPU result or checkpoint load is claimed.

## DCNet (`dcnet`)

- **Source URL and pinned SHA:** https://github.com/ozmig77/dcnet/tree/68c79d38569f01ca39c3b4ea641b3b7eb2ccb5fb — `68c79d38569f01ca39c3b4ea641b3b7eb2ccb5fb` (`workbench/registry/models.yaml`, `dcnet.upstream_commit_sha`).
- **Official dataset entrypoint:** `workbench/third_party/DCNet/test.py:test` constructs `ExpertDataLoader` from saved `config.json`. `data_loader/data_loaders.py:ExpertDataLoader.__init__` selects config categories (`dress`, `shirt`, `toptee`); `CE_dataset.py:CE.__init__` loads `captions/cap.{category}.glove.val.pkl` for query records and `image_splits/split.{category}.val.json` for `val_trg`. `CE.__getitem__` reads reference/target IDs and precomputed `wv` arrays from the PKL. `val_trg` turns each ordered split ID into a gallery item. `test.py:test` seeds Python/NumPy/Torch with zero before evaluation.
- **Official preparation functions:** `preprocess/process_cap.py` (top-level script) builds train vocabulary and writes `captions/glove_vecs.pkl` plus per-split `cap.{category}.glove.{split}.pkl`; `preprocess/resize_img.py:resize_images_parallel` writes resized images using direct 256×256 PIL resize to `resized_images/`. `CE_dataset.py:CE.__getitem__` consumes only `cap.*.glove.val.pkl` and resized image files at eval. `glove_vecs.pkl` is written by prep, but no inspected evaluator reads it; it is not an additional required evaluation file. `parse_config.py:ConfigParser.__init__` needs the run-directory `config.json`.
- **Official text preprocessing:** `process_cap.py` builds a vocabulary from all `cap*train.json` captions, lowercases, replaces hyphen with space and removes periods, calls `nltk.tokenize.word_tokenize`; it looks vectors up in spaCy `en_vectors_web_lg`. Missing vector words occurring more than twice receive unseeded `np.random.normal(0, 0.3, (300,))`; missing words with count ≤2 are not put in vocab and are dropped when validation `wv` is assembled. Both annotation captions' surviving vectors are stacked in source order. `CE_dataset.py:CE.collate_fn` truncates to max text length 30. These generated PKLs contain the realized vectors; recreating with the same raw files can change OOV embeddings, so exact author/prepared PKLs are preferred for a faithful replay. `test.py` imports `get_we_parameter` but does not call it; runtime OOV fallback in `utils/text2vec.py:get_we_parameter` is not part of this test path.
- **Official image preprocessing:** `resize_img.py:resize_images_parallel` distorts each source image to square 256×256; eval `data_loaders.py:dataset_loader` then applies `CenterCrop(224)`, `ToTensor`, ImageNet mean/std normalization. Standard config uses ImageNet-pretrained ResNet-50 (`configs/ce/fashioniq_dcnet.json`; `model/model.py:CENet.__init__`). DeepFashion DenseNet-169 is a distinct optional `fashioniq_dcnet_deep.json` route requiring `deepfashion/logdir/deepfashion_densenet/best_ckpt.pth.tar`, not the registered standard config.
- **Native evaluation protocol:** `trainer/trainer_joint.py:TrainerJoint._valid_epoch` builds gallery image features, composes both composition and correction score matrices, sets reference score to `-10e10` in both matrices, and ranks top 50. `model/metric.py:compute_score` computes binary target-hit R@10/R@50 per query. Combined score is `log_softmax(score_comp) + log_softmax(score_corr)` before ranking. `recall_avg` and `recall_avg_corr` average branch recalls across categories; `comb_avg` averages the three-category combined R@10/R@50 values. Gallery remains complete split order: `fashioniq_full_gallery_ref_excluded`.
- **Gallery construction:** per-category `val_trg` reads the entire ordered `split.{category}.val.json`; evaluator indexes references into that gallery and masks them, rather than constructing pair union (`CE_dataset.py:CE.__init__`, `TrainerJoint._valid_epoch`). Targets are ground-truth IDs in annotation PKLs.
- **Checkpoint routing:** `test.py` accepts `--resume <run-directory>`. `parse_config.py:ConfigParser.__init__` reads `<resume>/config.json`, sets validation mode/output directories, and initializes modules from config. `base/base_trainer.py:BaseTrainer.__init__` routes to `_resume_checkpoint`, which reads `<resume>/trained_model.pth` and loads checkpoint `state_dict`. The native run-directory contract therefore requires both `config.json` and `trained_model.pth`; `best_score.pt`, logs, and epoch checkpoints are not required by this loader. `test.py`'s `TrainerJoint` call is the evaluation route. README links author run directories but does not identify a verified local folder/hash. Registry correctly models `artifact_type: run_directory` and those two required files.
**Official evaluation DataLoader behavior:** `data_loaders.py:ExpertDataLoader.__init__` makes per-category validation DataLoaders with batch size 8, `shuffle=False`, `drop_last=False`, and gallery loaders with batch size 100, `shuffle=False`, `drop_last=False`; the test-mode query/gallery loaders use the analogous ordered, non-dropping setup (query batch size requested by caller, gallery batch size 100). The official evaluator consumes these ordered loaders in `TrainerJoint._valid_epoch`.
- **Current workbench implementation:** registry declares native/supported `fashioniq_full_gallery_ref_excluded`, `fashioniq_dcnet`, run-directory variant; `DCNetAdapter.command` calls `test.py --resume <directory>` (`workbench/backend/adapters/models.py:DCNetAdapter.command`). `fashioniq_layout.py:dcnet_paths` and preparation contract require GloVe validation PKLs, split files, and resized images; `prepare_model.py:status` only reports manual status. `runtime.py:runtime_blockers` checks source pin, checkpoint mapping, command, environment, contract paths, and external weight. Registry mapping remains unverified and no run is ready. Generic `src/evaluation/fashioniq.py:build_fashioniq_gallery` does not implement the `fashioniq_full_gallery_ref_excluded` ID; DCNet's actual adapter delegates its ranking to upstream `TrainerJoint._valid_epoch`.
- **Verified match:** native protocol mapping is correct: full ordered validation split, reference excluded, dual branch log-softmax fusion. Adapter CLI matches README and source `test.py` parser (`--resume`). The adapter routes to official code; no inference/result parity has been run.
**Confirmed mismatch:** workbench's generic `src/evaluation/fashioniq.py:build_fashioniq_gallery` supports internal `fashioniq_original` and `fashioniq_val` modes, not the registered `fashioniq_full_gallery_ref_excluded` mode; this generic evaluator cannot reproduce DCNet's full-split reference-masked protocol. The official adapter routes to native DCNet instead, so this remains an incomplete generic implementation rather than evidence that the adapter changes results. The `fashioniq_dcnet` prep contract correctly requires the three `cap.*.glove.val.pkl` artifacts, not the generated-but-unused `glove_vecs.pkl`. `fashioniq_layout.py:dcnet_paths` omits raw `images` and raw caption inputs that `preparation_contracts.yaml:dcnet_fashioniq` separately requires; combined preflight uses the preparation contract. No verified run directory/hash or actual generated artifacts exist in evidence. Do not conflate `fashioniq_original_split` with DCNet's reference-excluded evaluator.
- **Unresolved question:** exact author Drive folder member/content mapping and SHA of its `config.json`/`trained_model.pth`; whether author validation PKLs or only reproducible preprocessing outputs are available; exact cached ResNet-50 full digest.
- **Exact PC verification still owed:** verify both run-directory files and author mapping/hash; preserve config and state-dict pairing; verify Python 3.7.7/PyTorch 1.4.0/torchvision 0.5.0 and CUDA; stage/verify all three GloVe validation PKLs and 256-resized JPEGs; verify ResNet-50 weights; run `python test.py --resume <run-directory>` from DCNet root on GPU; capture native per-category branch/combined recalls and compare with author-reported evidence.
