## CLVC-Net (`clvc_net`)

- **Source URL and pinned SHA:** https://github.com/iLearn-Lab/SIGIR21-CLVC-Net/tree/bd9b6889489806cb60676597880f91d918b279cb — `bd9b6889489806cb60676597880f91d918b279cb` (`workbench/registry/models.yaml`, `clvc_net.upstream_commit_sha`).
- **Official dataset entrypoint:** `workbench/third_party/CLVCNet/datasets.py:FashionIQ.__init__`, `FashionIQ.__getitem__`, `FashionIQ.get_test_queries`, `FashionIQ.get_test_targets`. Constructor reads `captions/cap.{category}.{split}.json` and `image_splits/split.{category}.{split}.json`; image files are under `<fashioniq_path>/resized_image/<category>/<id>.jpg`. Each annotation retains its reference (`candidate`), target, and two captions. `FashionIQ.get_test_queries` associates IDs by `self.images.index`; `get_test_targets` defaults `gallery_all=False` and builds first-seen ordered reference/target endpoint union. `train.py:load_dataset` chooses a single category via `--name`; README's three FashionIQ commands train `dress`, `shirt`, and `toptee` separately.
- **Official preparation functions:** no FashionIQ resize/preprocessing script is in pinned CLVCNet. `README.md` instructs resizing with the external FashionIQ `start_kit/resize_images.py`; `datasets.py:FashionIQ.__init__` assumes its `resized_image` output exists. Training/evaluation dataset objects are created by `train.py:load_dataset`. This is not evidence for a specific local resize implementation beyond README's reference.
- **Official text preprocessing:** `workbench/third_party/CLVCNet/datasets.py:FashionIQ.concat_text` constructs `"<BOS> {cap1} <AND> {cap2} <EOS>"`. `workbench/third_party/CLVCNet/text_model.py:SimpleVocab.tokenize_text` drops non-ASCII bytes, removes `string.punctuation`, lowercases, strips, and whitespace-splits; `SimpleVocab.encode_text` maps unknown tokens to ID 0. `workbench/third_party/CLVCNet/train.py` builds vocabulary from `FashionIQ.get_all_texts`, which supplies the two raw captions separately, while `FashionIQ.get_test_queries` passes the marker-wrapped pair. Tokenization strips angle brackets, so marker spellings become `bos`, `and`, `eos`; these are not the reserved vocabulary keys `<BOS>`, `<AND>`, `<EOS>` and map to ID 0 unless caption vocabulary independently contains them. No correction dictionary is loaded for CLVCNet FashionIQ.
- **Official image preprocessing:** `train.py:load_dataset` evaluation transform is `Resize(256)`, `CenterCrop(224)`, `ToTensor`, ImageNet mean/std normalization; `datasets.py:FashionIQ.get_img` opens RGB images from `resized_image/<category>`. Training uses `Resize(256)`, random crop and horizontal flip. Both local/global branches initialize `resnet.resnet50(pretrained=True)` in `model.py:img_backbone.__init__`; this is a runtime ImageNet weight dependency. The README's external pre-resizing plus source `Resize(256)` is the actual chain; no CLIP transform is involved.
- **Native evaluation protocol:** `workbench/third_party/CLVCNet/test.py:test` (FashionIQ branch) accumulates query/gallery features in Python lists by `params.batch_size`, without a PyTorch `DataLoader`. It L2-normalizes branch and concatenated features, computes query-gallery dot products, masks each reference slot to `-10e10`, descending-sorts, and computes percent per-category R@1/R@10/R@50. Query features concatenate normalized local/global composed features; gallery features concatenate normalized local/global image features (`workbench/third_party/CLVCNet/model.py:compose_local.compose_img_text`, `compose_global.compose_img_text`). `workbench/third_party/CLVCNet/train.py:train_and_evaluate` evaluates categories separately but defines no macro-recall helper. `test.py` has no CLI `main`, model construction, or checkpoint loader; README's `python test.py` is not a checkpoint-replay entrypoint.
- **Gallery construction:** `workbench/third_party/CLVCNet/datasets.py:FashionIQ.get_test_targets` uses pair-union reference+target IDs in annotation order with first occurrence retained; `workbench/third_party/CLVCNet/test.py:test` excludes each reference before ranking. This is `fashioniq_val_split`, not full validation split.
- **Checkpoint routing:** `workbench/third_party/CLVCNet/train.py:train_and_evaluate` saves `local_model.pt` and `global_model.pt` in a model directory. README Usage supplies separate commands for dress, shirt, and toptee. Pinned source provides no test-time loader for these files. README links `CLVCNET.zip`; its file-to-category/local/global association is not established by inspected code. Registry currently has one `author_drive_unresolved` variant, `checkpoint_serialization: whole_model`, and `category_model_policy: shared` (`workbench/registry/models.yaml`, interpreted by `workbench/backend/registry.py:load_registry`).
- **Auxiliary assets:** evaluation needs torchvision ResNet-50 ImageNet pretrained weights (`workbench/third_party/CLVCNet/model.py:img_backbone.__init__`, `pretrained=True`) and resized category JPEGs. Workbench `clvc_net_fashioniq` preparation contract records published weight URL and SHA prefix `19c8e357`, not full digest (`workbench/registry/preparation_contracts.yaml`). No caption-correction asset is used by source.
- **Current workbench implementation:** `workbench/backend/adapters/models.py:CLVCNetAdapter` names `test.py` but inherits `OfficialScriptAdapter.command`, which raises `NotImplementedError`; `workbench/registry/models.yaml` records `BLOCKED_NO_SOURCE_REPLAY`/`COMMAND_BLOCKED_SOURCE_ENTRYPOINT` (read by `workbench/backend/registry.py:load_registry`). `workbench/backend/fashioniq_layout.py:clvc_resized_paths` requires category `resized_image`, train/val annotations, val splits. `workbench/registry/preparation_contracts.yaml:clvc_net_fashioniq` declares manual start-kit resizing. Local `src/datasets/fashioniq.py:FashionIQDataset.__getitem__` plus `compose_fashioniq_caption` provide a different plain caption path, but blocked adapter never invokes it. Registry protocol is `fashioniq_val_split`.
- **Verified match:** reference exclusion and endpoint-union gallery semantics match registered `fashioniq_val_split` (`workbench/registry/models.yaml`, interpreted by `workbench/backend/registry.py:load_registry`; source behavior is `workbench/third_party/CLVCNet/datasets.py:FashionIQ.get_test_targets` and `workbench/third_party/CLVCNet/test.py:test`). This establishes protocol mapping only, not runnable replay.
- **Confirmed mismatch:** source trains separate local/global whole models per category, while registry sets `category_model_policy: shared` and records one unresolved checkpoint variant (`workbench/registry/models.yaml`, read by `workbench/backend/registry.py:load_registry`; upstream `workbench/third_party/CLVCNet/train.py:load_dataset`, `train_and_evaluate`). Treating one pair as covering all categories risks wrong category checkpoints. Workbench local default caption construction omits CLVC's BOS/AND/EOS markers and uses another tokenizer, but no CLVC adapter invokes it; this is not evidence of changed native input. No CLVC adapter command/checkpoint loader exists.
- **Unresolved question:** which exact author ZIP members map to each category's local/global whole-model files, and whether any public checkpoint pair covers all three independent categories. Full torchvision weight digest and exact external start-kit resize behavior also remain unverified.
- **Exact PC verification still owed:** obtain author-attested category/local/global file mapping and trusted hashes; stage three category pairs and required ResNet-50 asset; provide source-backed replay entrypoint or reconstruct only after provenance approval; verify isolated Python 3.7.6/PyTorch 1.6.0 plus torchvision/CUDA; execute every category on GPU and compare native per-category recalls to author evidence. No GPU result or checkpoint load is claimed.

## DCNet (`dcnet`)

- **Source URL and pinned SHA:** https://github.com/ozmig77/dcnet/tree/68c79d38569f01ca39c3b4ea641b3b7eb2ccb5fb — `68c79d38569f01ca39c3b4ea641b3b7eb2ccb5fb` (`workbench/registry/models.yaml`, `dcnet.upstream_commit_sha`).
- **Official dataset entrypoint:** `workbench/third_party/DCNet/test.py:test` constructs `ExpertDataLoader` from saved `config.json`. `data_loader/data_loaders.py:ExpertDataLoader.__init__` selects config categories (`dress`, `shirt`, `toptee`); `CE_dataset.py:CE.__init__` loads `captions/cap.{category}.glove.val.pkl` for query records and `image_splits/split.{category}.val.json` for `val_trg`. `CE.__getitem__` reads reference/target IDs and precomputed `wv` arrays from the PKL. `val_trg` turns each ordered split ID into a gallery item. `test.py:test` seeds Python/NumPy/Torch with zero before evaluation.
- **Official preparation functions:** `workbench/third_party/DCNet/preprocess/process_cap.py` (top-level script) builds train vocabulary and writes `captions/glove_vecs.pkl` plus per-split `cap.{category}.glove.{split}.pkl`; `workbench/third_party/DCNet/preprocess/resize_img.py:resize_images_parallel` writes resized images using direct 256×256 PIL resize to `resized_images/`. `workbench/third_party/DCNet/data_loader/CE_dataset.py:CE.__getitem__` consumes only `cap.*.glove.val.pkl` and resized image files at evaluation. `glove_vecs.pkl` is written by prep, but no inspected evaluator reads it; it is not an additional evaluation file. `workbench/third_party/DCNet/parse_config.py:ConfigParser.__init__` needs run-directory `config.json`.
- **Official text preprocessing:** `workbench/third_party/DCNet/preprocess/process_cap.py` builds vocabulary from all train caption JSONs, lowercases, replaces hyphen with space, removes periods, tokenizes with `nltk.tokenize.word_tokenize`, then looks vectors up in spaCy `en_vectors_web_lg`. Missing vector words occurring more than twice receive unseeded `np.random.normal(0, 0.3, (300,))`; missing words with count ≤2 are excluded from vocabulary and dropped when validation `wv` is assembled. Surviving vectors from both captions are stacked in source order. `workbench/third_party/DCNet/data_loader/CE_dataset.py:CE.collate_fn` truncates to maximum text length 30. Generated PKLs contain realized vectors; regenerating with same raw files can change OOV embeddings, so exact author/prepared PKLs are preferred. `workbench/third_party/DCNet/test.py:test` imports `get_we_parameter` but does not call it; runtime OOV fallback in `workbench/third_party/DCNet/utils/text2vec.py:get_we_parameter` is not part of this test path.
- **Official image preprocessing:** `workbench/third_party/DCNet/preprocess/resize_img.py:resize_images_parallel` distorts each source image to square 256×256; evaluation `workbench/third_party/DCNet/data_loader/data_loaders.py:dataset_loader` then applies `CenterCrop(224)`, `ToTensor`, ImageNet mean/std normalization. Standard `workbench/third_party/DCNet/configs/ce/fashioniq_dcnet.json` uses ImageNet-pretrained ResNet-50 (`workbench/third_party/DCNet/model/model.py:CENet.__init__`). DeepFashion DenseNet-169 is a distinct optional `fashioniq_dcnet_deep.json` route requiring `deepfashion/logdir/deepfashion_densenet/best_ckpt.pth.tar`, not the registered standard config.
- **Native evaluation protocol:** `workbench/third_party/DCNet/trainer/trainer_joint.py:TrainerJoint._valid_epoch` builds gallery image features, composes composition and correction score matrices, masks each reference score to `-10e10`, and ranks top 50. `workbench/third_party/DCNet/model/metric.py:compute_score` computes binary target-hit R@10/R@50 per query. Combined ranking score is `log_softmax(score_comp) + log_softmax(score_corr)`. `recall_avg` and `recall_avg_corr` average branch recalls across categories; `comb_avg` averages three-category combined R@10/R@50 values. Complete split order is `fashioniq_full_gallery_ref_excluded`.
- **Gallery construction:** `workbench/third_party/DCNet/data_loader/CE_dataset.py:CE.__init__` in `val_trg` loads entire ordered `split.{category}.val.json`; evaluator `workbench/third_party/DCNet/trainer/trainer_joint.py:TrainerJoint._valid_epoch` indexes references into that gallery and masks them instead of constructing pair union. Targets are ground-truth IDs in validation annotation PKLs.
- **Checkpoint routing:** `test.py` accepts `--resume <run-directory>`. `parse_config.py:ConfigParser.__init__` reads `<resume>/config.json`, sets validation mode/output directories, and initializes modules from config. `base/base_trainer.py:BaseTrainer.__init__` routes to `_resume_checkpoint`, which reads `<resume>/trained_model.pth` and loads checkpoint `state_dict`. The native run-directory contract therefore requires both `config.json` and `trained_model.pth`; `best_score.pt`, logs, and epoch checkpoints are not required by this loader. `test.py`'s `TrainerJoint` call is the evaluation route. README links author run directories but does not identify a verified local folder/hash. Registry correctly models `artifact_type: run_directory` and those two required files.
