# Phase 2 source audit — CSMCIR, LIMN, ENCODER, PAIR

Scope: executable FashionIQ validation paths in four pinned, read-only upstream checkouts. Source pins below are the inventory pins, not proof that checkpoint/runtime reproduction has run. `workbench/docs/PROTOCOL_AUDIT.md` keeps the three protocols distinct: `fashioniq_original_split` (full validation gallery, reference eligible), `fashioniq_full_gallery_ref_excluded` (same gallery, reference excluded), and `fashioniq_val_split` (ordered endpoint-union gallery, reference excluded).

## CSMCIR

- **Source URL and pinned SHA:** [qzp2018/CSMCIR](https://github.com/qzp2018/CSMCIR), `774f94e2076ff17ea91703a6239d2a08f0e1a44e` (`workbench/registry/models.yaml`, `csmcir`).
- **Official dataset entrypoint:** `src/data_utils_csmcir.py:FashionIQDataset.__init__`, `__getitem__`; fixed root is `Path(__file__).absolute().parents[1] / 'fashionIQ_dataset'`, i.e. the source checkout's `fashionIQ_dataset/`. It reads `captions/cap.{category}.val.json`, `qwen_captions/{category}_cot_val.json`, and `image_splits/split.{category}.val.json`. Validation enumerates `dress`, `toptee`, `shirt` in `src/validate_blip_csmcir.py:blip_validate_fashioniq` (not registry/helper order). The README layout says `fashionIQ_dataset/{captions,images,image_splits}` and example image names are `.jpg` (`README.md`, “Data Preparation”); executable `FashionIQDataset.__getitem__` instead opens `images/{id}.png` for both reference and gallery. This internal extension discrepancy is unresolved and can make the documented raw download fail at evaluation.
- **Official preparation functions:** `workbench/scripts/prepare_dataset.py:validate_fashioniq`, `prepare_csmcir` validate standard FashionIQ paths and create/check `workbench/third_party/CSMCIR/fashionIQ_dataset -> FASHIONIQ_ROOT`; this satisfies source's fixed-root expectation, not the `.png`/`.jpg` discrepancy. The source does not convert original files. `src/data_utils_csmcir.py:targetpad_transform` defines the evaluator transform.
- **Official text preprocessing:** `src/validate_blip_csmcir.py:generate_fiq_val_predictions` flattens the two captions in annotation order and constructs `f"{cap1.strip('.?, ').capitalize()} and {cap2.strip('.?, ')}"`. It then calls `txt_processors['eval']`. `src/lavis/processors/blip_processors.py:BlipCaptionProcessor.pre_caption` lowercases, replaces only `[.!\"()*#:;~]` with spaces, collapses repeated spaces, strips, and word-truncates to 50; configured prompt defaults to empty. `blip2_qformer_cir_align_prompt_csmcir.py:Blip2QformerCirAlignPromptCSMCIR.inference` tokenizes with `padding='max_length'`, `truncation=True`, `max_length=self.max_txt_len` (default 32). Its `text_cot` argument is not consumed in that inference body. `src/data_utils_csmcir.py:FashionIQDataset.__getitem__` nevertheless loads Qwen `Final_Caption` for reference and target and returns them. The candidate-gallery caption actually used for indexing is separately loaded by `src/utils_csmcir.py:extract_index_blip_caption_features` from source-root `COT_ours2/fashioniq/{dress,shirt,toptee}_cot_val.json` and passed to `extract_target_caption_features`; the query's Qwen captions do not replace this asset.
- **Official image preprocessing:** `src/validate_blip_csmcir.py:blip_validate_fashioniq` fixes input dimension 224 and default `targetpad`, ratio 1.25. `src/data_utils_csmcir.py:TargetPad.__call__` adds symmetric constant-zero padding when aspect ratio is at least 1.25; `targetpad_transform` then uses torchvision `Resize(224, interpolation=PIL.Image.BICUBIC)` (scalar/short-edge resize), `CenterCrop(224)`, RGB conversion, `ToTensor`, and CLIP mean `(0.48145466,0.4578275,0.40821073)` / std `(0.26862954,0.26130258,0.27577711)`. No torchvision version is pinned in `src/requirements.txt`; exact installed-version behavior remains a runtime item.
- **Native evaluation protocol:** `src/validate_blip_csmcir.py:blip_validate_fashioniq`, `generate_fiq_val_predictions`, `compute_fiq_val_metrics`. Gallery index is every ID in the category's ordered validation split. Query uses candidate/reference ID and target ID from each validation caption annotation. Prediction is `Blip2QformerCirAlignPromptCSMCIR.inference(reference_features, index_features[0], input_captions, captions_cot)`, whose returned score is maximum query-token/target-feature similarity (`src/lavis/models/blip2_models/blip2_qformer_cir_align_prompt_csmcir.py:inference`). Evaluator converts similarity to `1 - score`, sorts ascending, and does **not** mask or remove the reference (`compute_fiq_val_metrics`). Native protocol is `fashioniq_original_split`.
- **Gallery construction:** `src/data_utils_csmcir.py:FashionIQDataset.__init__` reads `split.{category}.val.json` unchanged for `classic`; it does not build a pair union. `classic` gallery includes reference.
- **Recall and category aggregation:** `src/validate_blip_csmcir.py:compute_fiq_val_metrics` counts each query's single target in ranks `<=10` and `<=50`, divides hits by category query count and multiplies by 100. `blip_validate_fashioniq` computes arithmetic means of the three category R@10s and R@50s, then `average_recall=(average_R10+average_R50)/2`; this is a category macro, not query-weighted aggregation.
- **Checkpoint routing:** one checkpoint, `fashioniq_tuned_clip_best.pt`, is loaded into `checkpoint[blip_model.__class__.__name__]` with `strict=False` by `blip_validate_fashioniq`. Registry maps it to `checkpoint_id: fashioniq`, author Hugging Face URL, no published SHA (`workbench/registry/models.yaml`, `csmcir.checkpoint_variants`). It is one model evaluated across all three categories, not three category checkpoints.
- **Auxiliary assets:** three Qwen category JSONs under FashionIQ `qwen_captions/` are read by the dataset; registry source is author Hub revision `cf0c19bb346266c295b4b5772ebf03bd1c4f0467`, files have no published SHA (`workbench/registry/auxiliary_assets.yaml`, CSMCIR Qwen entries). Three additional `COT_ours2/fashioniq/{category}_cot_val.json` files are opened from model source by `utils_csmcir:extract_index_blip_caption_features`; workbench records these as source `none`, provenance `UNVERIFIED`. Source model initialization also loads LAVIS BLIP-2 pretrained weights via `configs/models/blip2/blip2_pretrain.yaml` (`blip2_pretrained.pth`) before fine-tuned state overlay; no corresponding CSMCIR external-asset record is present in `auxiliary_assets.yaml` or `preparation_contracts.yaml`.
- **Current workbench implementation:** `workbench/registry/models.yaml:csmcir` declares standard layout and `fashioniq_original_split`. `workbench/backend/adapters/models.py:CSMCIRAdapter.command` invokes `src/validate_blip_csmcir.py --dataset fashionIQ --blip-model-path <checkpoint>`; CSMCIR cwd is `src` (`workbench/scripts/evaluate_models.py:source_cwd`). `workbench/backend/fashioniq_layout.py:standard_paths` checks standard paths; registry `fashioniq_image_extensions: [".png"]` and both `workbench/backend/runtime.py:preflight` and `workbench/scripts/doctor.py` call `image_extension_problems` to check every validation image. `prepare_dataset.py` creates the fixed symlink. `src/evaluation/fashioniq.py:build_fashioniq_gallery` now accepts all three registry protocol IDs plus legacy aliases; `evaluate_fashioniq_recall(..., reference_ids=...)` implements reference exclusion. For exclusion, workbench removes the reference column; pinned evaluators mask its score to `-10e10` before sorting. Those operations agree on the top-k hit test only while every other score clears that mask; they are not literally the same operation and numeric equivalence is not asserted. Workbench preparation/auxiliary registry still omits the LAVIS base checkpoint requirement; COT auxiliary provenance remains unverified.
- **Verified match:** native adapter command retains official `fashionIQ` default dispatch, checkpoint flag, and source-working-directory import context. Registry's intended protocol label is correct for full-split/reference-eligible semantics. Native category macro semantics are reflected by `workbench/backend/metrics_extraction.py:parse_csmcir_output`.
- **Confirmed mismatch:** raw FashionIQ README examples are `.jpg`, but executable `FashionIQDataset.__getitem__` opens `.png`. Workbench now catches this source/data mismatch in preflight for every validation image; it does not convert images. Generic gallery construction now accepts the registry IDs and includes the full-gallery reference-excluded family. Workbench preparation/auxiliary registry omits the LAVIS base checkpoint requirement, and COT auxiliary provenance remains unverified. ## LIMN (base iteration 0 only; not LIMN+)

- **Source URL and pinned SHA:** [iLearn-Lab/TPAMI24-LIMN](https://github.com/iLearn-Lab/TPAMI24-LIMN), `7d7bc9b116f594a65ac22457491edf28a88d3c3e` (`workbench/registry/models.yaml`, `limn`). Native source file is `LIMN/datasets.py`, `LIMN/model.py`, `LIMN/test.py`, and `LIMN/train.py`.
- **Official dataset entrypoint:** `LIMN/datasets.py:FashionIQ.__init__`, `get_test_data`. Root argument must end in `/` because `image_dir = path + 'resized_image'`; image path is `resized_image/{category}/{id}.jpg`. It reads one category per dataset object, category names exactly `dress`, `shirt`, `toptee`; `LIMN/train.py:load_dataset` runs each separately.
- **Exact annotations and splits:** `get_test_data` opens `image_splits/split.{category}.val.json`, `captions/cap.{category}.val.json`, `captions/correction_dict_{category}.json`. `FashionIQ.__init__` additionally opens/creates `{category}_train_data.json`; if absent, `train_init_process` requires `captions/cap.{category}.train.json` and that correction dictionary. Test caches are `{category}_train_data.json`, `test_queries_{category}.pkl`, `test_targets_{category}.pkl`; native code trusts present caches without freshness validation. Workbench replay uses `workbench/replay/common.py:isolated_cache_root` to provide a new temp root and only symlink raw immutable directories, avoiding stale cache reuse.
- **Official preparation functions:** `LIMN/README.md` directs FashionIQ image resize through FashionIQ `start_kit/resize_images.py` into `resized_image/`; it says correction dictionaries are provided in `correct_files/`. No executable resize or dictionary-copy function is in this pinned LIMN tree. Workbench `preparation_contracts.yaml:limn_fashioniq` records manual resize and manual placement from pinned `correct_files/`; `workbench/replay/limn.py:validate_dataset` checks train/val captions, split, corrections, and resized category directory.
- **Official text preprocessing:** `LIMN/datasets.py:FashionIQ.correct_text` lowercases; maps each `string.punctuation` character to a space; strips and whitespace-splits; does exact token lookup in loaded correction dictionary and joins with one space. `concat_text` returns corrected caption 0 + literal ` and ` + corrected caption 1. No additional prompt/case correction is applied after this. `LIMN/model.py:Backbone.extract_text_fea` calls OpenCLIP ViT-L/14 tokenizer. Pinned `open_clip_torch==2.20.0` (LIMN requirements/README) uses the default 77-token CLIP context and truncates overlength sequences, replacing final retained token with EOT (`open_clip/tokenizer.py:SimpleTokenizer.__call__`, v2.20.0).
- **Official image preprocessing:** `LIMN/train.py:load_dataset` calls `open_clip.create_model_and_transforms('ViT-L-14', pretrained=...)`, passes `preprocess_val` into dataset. Workbench replay reproduces the exact native factory call using loaded model visual `image_size`, `image_mean`, `image_std` (`workbench/replay/limn.py:replay_category`). With pinned `open_clip_torch==2.20.0`, `ViT-L-14` model config `image_size=224`; `open_clip.transform:image_transform` eval path does shortest-edge `Resize(224, BICUBIC)`, `CenterCrop(224)`, RGB, tensor, OpenAI CLIP mean/std. Upstream pins `torchvision==0.13.1`; validation does not use random train crop.
- **Native evaluation protocol:** `LIMN/test.py:test`. Query is `model.compose_query(reference_image, mod, dataset_type)[0]`, gallery vector is `model.compose_target(image, dataset_type)[0]`; both outputs are L2-normalized then cosine similarity (`all_queries.dot(all_imgs.T)`). The per-query reference gallery position is assigned `-10e10` before descending `argsort`; top-50 rankings are tested at K=1,10,50. `FashionIQ.get_test_data` builds `test_targets` as first-seen ordered union of each annotation's source then target, with IDs mapped to positions in full split. Native protocol `fashioniq_val_split`.
- **Gallery and reference handling:** endpoint-union only; reference is present in candidate feature list then score-masked to `-10e10` before ranking, not physically removed (`LIMN/datasets.py:get_test_data`; `LIMN/test.py:test`).
- **Recall/category aggregation:** `LIMN/test.py:test` reports category R@1/R@10/R@50 as percent of category queries with target in top K. Source does not emit an all-category macro. `LIMN/train.py:train_and_evaluate` chooses each independently trained category model using sum of that category's R@10 and R@50; that is a selection score, not an across-category macro. Workbench separately computes arithmetic category macro R@10, macro R@50, then mean only for all three complete categories (`workbench/replay/common.py:macro_aggregate`).
- **Checkpoint routing:** `LIMN/train.py:train_and_evaluate` saves one whole serialized model as `{iteration}_{category}_best_model.pt`; `LIMN/README.md` runs separate dress/shirt/toptee commands. Workbench metadata verifies base iteration-0 mappings/hashes: `0_dress_best_model.pt` SHA `96a335d4…fc1c`, `0_shirt_best_model.pt` SHA `9260c7f7…0d74`, `0_toptee_best_model.pt` SHA `79f663a1…cece` (`workbench/registry/models.yaml`, `base_iter0_*`). All three are required for complete macro.
- **Auxiliary assets:** manually staged `correct_files/correction_dict_{dress,shirt,toptee}.json` into FashionIQ `captions/`; resized category JPEGs generated by FashionIQ start-kit script. Whole-model checkpoint contains serialized model/backbone state; Python packages remain runtime prerequisites. LIMN `preparation_contracts.yaml` records no separate required pretrained-weight file.
- **Current workbench implementation:** `workbench/backend/adapters/models.py:LIMNAdapter.command` invokes `workbench/replay/limn.py`; `replay_category` checks pinned source, category checkpoint hash, required dataset files, `torch==1.12.1`, `torchvision==0.13.1`, `open_clip_torch==2.20.0`, CUDA; loads trusted whole model and calls pinned `LIMN/test.py:test` without reimplementing inference. `evaluate_categories` and `macro_aggregate` reject partial/misordered categories as complete macros. `fashioniq_layout.py:ilearn_resized_training_paths` includes three train captions and required val/correction/split/resized paths.
- **Verified match:** workbench protocol, inputs, caption normalization/order, category-local model routing, preprocessing factory/version, endpoint-union ordering, source-score masking, per-category Recall, and 3-way arithmetic macro are grounded in native source or explicit source-faithful wrapper. Macro is workbench aggregation, not falsely attributed to native `test.py`.
- **Confirmed mismatch:** registry `fashioniq_ilearn_resized_training` adds all three train captions even when replay selects one category; this is a harmless superset, not a semantic mismatch. `src/evaluation/fashioniq.py:build_fashioniq_gallery` now accepts all registry protocol IDs and legacy aliases, but dedicated replay does not call it. - **Exact PC verification still owed:** on GPU verify source pin, all three author checkpoint sizes/SHA-256, required raw and manually prepared data, exact isolated interpreter/package versions and CUDA; run the all-category replay (not a single-category diagnostic); retain three category outputs, arithmetic macro, stdout/stderr, provenance and digests.
