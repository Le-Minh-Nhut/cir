## Air-Know

### Source and official path

- Source: `https://github.com/iLearn-Lab/CVPR26-Air-Know`, pinned `workbench/third_party/AirKnow` at `6ab6fa95b746f85b08eea4cb66eb51448bce99b7` (pin and evaluator path recorded in `workbench/docs/UPSTREAM_SOURCE_AUDIT.md`).
- Official FashionIQ dataset entry: `workbench/third_party/AirKnow/datasets.py:FashionIQ.__init__`. It uses `path + 'resized_image'`, `path + 'image_splits'`, `path + 'captions'`; therefore caller path must end with a separator. Raw records are `captions/cap.{dress,shirt,toptee}.{train,val}.json`; validation gallery list is `image_splits/split.{category}.val.json`. `get_test_data(category)` reads those category-specific val files in listed/annotation order, maps `candidate` and `target` through `images.index`, and stores reference and target indices/data.
- Preparation functions: `FashionIQ.train_init_process()` reads all three training annotation files and correction dictionaries; `FashionIQ.get_test_data()` builds validation query/gallery data; `get_img()` / `get_test_img()` open `resized_image/{category}/{image_id}.jpg`, convert RGB, apply supplied transform. No source-side FashionIQ image-resize/preparation script was found. README data setup (`README.md`, FashionIQ data-preparation section) asks for FashionIQ data organized as `resized_image/{category}` and `correction_dict_{category}.json`; this is manual placement, not a pinned conversion function.
- Cache behavior: when `fashion_iq_data.json` is absent, `__init__` builds it and writes `test_queries_{dress,shirt,toptee}.pkl` and `test_targets_{dress,shirt,toptee}.pkl`; otherwise it loads those PKLs. Cache freshness is not checked (`datasets.py:FashionIQ.__init__`). These cache files are not among `workbench/backend/fashioniq_layout.py:ilearn_resized_paths` required paths.

### Text, image and noise handling

- `FashionIQ.correct_text()` lowercases each raw caption, translates every `string.punctuation` character to a space, strips/splits whitespace, applies exact per-token lookup in the category correction dictionary, and joins tokens with spaces. `concat_text()` composes caption 1 then caption 2 with literal ` and `. `get_test_data()` applies this to validation captions. Correction is required at `captions/correction_dict_{dress,shirt,toptee}.json`; no provenance for these files is pinned by Air-Know.
- `test_BLIP2.py:test()` sends the composed query string through `txt_processors["eval"]`. `lavis/processors/blip_processors.py:BlipCaptionProcessor.pre_caption()` lowercases; replaces only `[.!"()*#:;~]` with spaces; collapses repeated whitespace; strips; truncates to 50 words (`BlipCaptionProcessor` default); then the model tokenizer is applied. `lavis/models/blip2_models/blip2.py:Blip2Base.init_tokenizer()` loads `BertTokenizer.from_pretrained('/root/bert-base-uncased')` and adds `[DEC]`. `lavis/models/blip2_models/blip2_cir.py:Blip2QformerCir.extract_retrieval_compose()` tokenizes with `padding='max_length'`, truncation, `max_length=self.max_txt_len` (default 32). These two text stages are not the same normalization as `correct_text()`.
- `train_BLIP2.py:load_dataset()` uses `targetpad_transform(1.25, 224)` for FashionIQ; validation images in `get_test_data()` use `get_test_img()` with this same supplied transform. `data_utils.py:TargetPad.__call__()` RGB-converts via the dataset getter; when aspect ratio is at least 1.25 it symmetrically zero-pads the short dimension to target ratio; then `targetpad_transform()` applies bicubic `Resize(224)`, `CenterCrop(224)`, RGB conversion, `ToTensor`, CLIP normalization mean `(0.48145466, 0.4578275, 0.40821073)` / std `(0.26862954, 0.26130258, 0.27577711)`. `train_BLIP2.py` selects targetpad, not squarepad.
- Noise hook is `FashionIQ.shuffle()`, called in `train_BLIP2.py:load_dataset()` on the training set. It changes `fashioniq_data` candidate/caption/target assignments at sampled training indices (and labels). Validation lists are separately built by `get_test_data()` and `shuffle()` does not modify those lists. `test_BLIP2.py:test()` itself does not call `shuffle()` or pass a noise ratio. Do not call the training loader/shuffle as an evaluation-time noise operation; use evaluation ratio 0 and untouched val records.

### Native evaluation, checkpoint routing, assets

- Native eval is a callable function, not a clean standalone evaluator: `test_BLIP2.py:test(params, model, testset, category, txt_processors)` chooses one stored category query/target collection, forms query features from reference image + processed text, and gallery features from all targets. It computes matrix similarity `np.matmul(all_queries, all_imgs)`, squeezes, takes `max(-1)` over image query features, then masks each query's source index in the full gallery to `-10e10`. Target is checked among descending results for R@1/R@10/R@50; each is hit fraction ×100 (`test_BLIP2.py:test`).
- The dataset's `self.split = 'original-split'` and `get_test_data()`'s `original-split` branch enumerate every validation `images` entry in split-file order, not only endpoints. This is full-gallery reference-excluded behavior, not `fashioniq_original_split` (reference-eligible) and not pair-union `fashioniq_val_split`. Exclusion occurs in `test_BLIP2.py:test` at `sims[i, test_targets_id.index(t['source_img_id'])] = -10e10`.
- Air-Know `test_BLIP2.py:test()` calls `model.train()` at entry. Its FashionIQ branch does not switch to `model.eval()` (the `fashion200k` branch does). `torch.no_grad()` is used, but inference mode is not established; this is a confirmed evaluator-mode mismatch to a clean eval-mode run. A source `test_BLIP2.py` entrypoint/CLI/checkpoint loader is absent: the file defines functions, while `train_BLIP2.py` invokes those functions during training and saves whole model as `best_model.pt`/`model_epoch_{epoch}.pt`. Thus standalone checkpoint loading and inference path remain unavailable in pinned code.
- Category result is a tuple list `dress_r1/r10/r50`, etc. `train_BLIP2.py:train_and_evaluate()` accumulates `t[1][1]` (R@10) across three categories only for best-checkpoint selection; it saves per-category metric keys, not a macro R@10/R@50 result. No native category macro aggregation is implemented in `test_BLIP2.py:test()`.
- Workbench filename/noise mapping in `workbench/registry/models.yaml:airknow`: `airknow_fiq_0.5.pt` → 50% and `airknow_fiq_0.8.pt` → 80%; both metadata rows set `evaluation_noise_pct: 0`, status `NO_CLEAN_CHECKPOINT`. The pinned trainer takes `--noise_ratio` (`train_BLIP2.py` parser) and its `shuffle()` applies that ratio to training records. Source trainer itself saves generic `best_model.pt`; it does not emit the registry Hub filenames or a separate eval checkpoint loader. Filename-to-training-noise association is registry/Hub metadata, not a checked checkpoint payload; no weight was downloaded or inspected.
- Additional runtime assets: model config `lavis/configs/models/blip2/blip2_pretrain.yaml` points `pretrained` to LAVIS `blip2_pretrained.pth`; tokenizer is loaded from `/root/bert-base-uncased` (`lavis/models/blip2_models/blip2.py:Blip2Base.init_tokenizer`). Correction dictionaries and cache PKLs are dataset prerequisites. None of these auxiliary records appears in `workbench/registry/auxiliary_assets.yaml` for `airknow` (that file currently contains only CSMCIR entries).

### Workbench comparison and findings

- Contract: `workbench/registry/models.yaml` declares `manual_ilearn_resized`, `fashioniq_ilearn_resized`, literature label `original`, and `fashioniq_full_gallery_ref_excluded`; checkpoint metadata is as above. `workbench/backend/fashioniq_layout.py:ilearn_resized_paths()` checks captions, split files, `resized_image/{category}` directories, val annotations and correction dictionaries. This matches source-required val path/shape, but misses source cache PKLs and does not validate image contents/provenance. `workbench/scripts/prepare_dataset.py:required_layout()` checks only standard images. `prepare_model.py:status()` has no iLearn preparation contract to load and, when `preparation_id` is absent, falls back to standard layout checks rather than the model's registered iLearn layout; runtime preflight independently uses `fashioniq_required_paths()` in `workbench/backend/registry.py` and the layout helper in `workbench/backend/runtime.py`.
- Protocol metadata: **verified match** for full gallery order and reference exclusion, based on the source branch and explicit score mask above. It is not an exact metric/command match: Air-Know's mode remains `train()`, source exports no query rows, and current shared evaluation does not implement this protocol.
- Adapter: `workbench/backend/adapters/models.py:AirKnowAdapter` only names `test_BLIP2.py`; inherited `OfficialScriptAdapter.command()` raises `NotImplementedError`. Current preflight therefore does not have a callable official evaluator command. `src/evaluation/fashioniq.py:build_fashioniq_gallery()` accepts internal names `fashioniq_original` and `fashioniq_val`, not registered `fashioniq_full_gallery_ref_excluded`, and its `recall_at_k()` has no reference mask. `fashioniq_encoder.py` masks reference but uses pair-union gallery; it is not Air-Know's protocol. No claim of function-name equivalence is made.
- **Confirmed mismatches:** Air-Know evaluator leaves FashionIQ model in train mode; upstream category loop selects sum of R@10 rather than category macro; workbench generic evaluator lacks registered full-gallery/ref-excluded logic; adapter cannot build command. Preparation status does not account for caches or external BLIP/BERT assets.
- **Unresolved question:** Which exact author Hub checkpoint bytes and local BLIP-2/BERT weights correspond to the intended architecture/runtime, and whether an author evaluator wrapper exists outside pinned `test_BLIP2.py`; none was verified here.
- **PC verification still owed:** confirm source SHA/clean tree; identify correct trailing-slash FashionIQ root and validate resized image/correction dictionary provenance and cache freshness; verify local BERT and LAVIS pretrained weights; fetch and hash-check both Hub artifacts and load each with source-compatible code; run category eval in `model.eval()` and separately reproduce pinned `model.train()` behavior; capture per-query rankings and per-category R@10/R@50, then reconcile registry paper scores and macro convention. No such PC check was performed.

## ConeSep

- Preparation functions: `FashionIQ.train_init_process()`, `get_test_data()`, `get_img()`, and `get_test_img()` have same data responsibilities as listed, but this evidence comes from ConeSep's own source (`datasets.py`). ### Text, image and noise handling

- `datasets.py:FashionIQ.correct_text()` lowercases, translates all `string.punctuation` characters to spaces, whitespace-tokenizes, performs exact category dictionary substitutions, joins with spaces; `concat_text()` keeps source caption order and inserts ` and `. `get_test_data()` applies it to raw val annotation captions. Files `captions/correction_dict_{dress,shirt,toptee}.json` are required but their provenance is not pinned.
- `test.py:test()` applies `txt_processors['eval']`: this tree's `lavis/processors/blip_processors.py:BlipCaptionProcessor.pre_caption()` lowercases, replaces regex class `[.!"()*#:;~]` with spaces, collapses whitespace, trims, truncates at default 50 words. The model's `Blip2Base.init_tokenizer()` in `lavis/models/blip2_models/blip2.py` uses `BertTokenizer.from_pretrained('/root/bert-base-uncased')`, adds `[DEC]`. `ConeSep.extract_retrieval_compose()` (`lavis/models/blip2_models/ConeSep.py`) uses max-length padding and truncation with `max_length=self.max_txt_len` (default 32). Validation target images use `FashionIQ.get_test_img()` with supplied transform.
- Noise injection is `FashionIQ.shuffle()` in `datasets.py`, called by `train.py:load_dataset()` after the train dataset is constructed. It randomly reassigns training candidate/caption/target fields according to `noise_ratio`. `test.py:test()` does not call it; validation query/gallery lists are separate from `fashioniq_data` and are not altered by this hook. For evaluation, do not run training loader's shuffle; training ratio is not evaluation noise.

### Native evaluation, checkpoint routing, assets

- `test.py:test(params,model,testset,category,txt_processors)` is callable but has no standalone CLI/checkpoint-loading main. It calls `model.eval()`, encodes each query from reference image + processed text, encodes gallery targets, computes `np.matmul(all_queries, all_imgs)`, `squeeze()`, then `max(-1)` across image query-token axis, and sets reference gallery similarity to `-10e10`. It ranks descending and returns R@1/R@10/R@50 as percentages (hit count divided by query count ×100), per selected category (`test.py:test`).
- `datasets.py:FashionIQ.__init__` sets `split='original-split'`; `get_test_data()` takes the `original-split` branch and inserts every val split image in exact split-file order. `test.py:test()` masks `source_img_id` after score construction and before recall. Thus this source does implement `fashioniq_full_gallery_ref_excluded`, not reference-included `fashioniq_original_split` or the pair-union `fashioniq_val_split`.
- `train.py:train_and_evaluate()` loops `dress`, `shirt`, `toptee`, sums each category's R@10 (`t[1][1]`) for model selection, writes per-category metric entries in `metrics_best.json`, and serializes full models as `model_epoch_{epoch}.pt` / `best_model.pt`. `test.py` does not produce a three-category macro R@10/R@50. It directly uses `model.eval()` (unlike Air-Know).
- Registry `workbench/registry/models.yaml:conesep` maps `ConeSep-FIQ-N0.2.pt`→20%, `ConeSep-FIQ-N0.5.pt`→50%, `ConeSep-FIQ_N0.8.pt`→80%, all evaluation noise 0, `NO_CLEAN_CHECKPOINT`. The source CLI has `--noise_ratio` and `FashionIQ.shuffle()` at that rate; training saves generic `best_model.pt`, no official evaluator routes a Hub file. Filename metadata indicates training noise but no checkpoint payload/hash inspected.
- Auxiliary runtime inputs: `lavis/configs/models/blip2/blip2_pretrain.yaml` uses LAVIS `blip2_pretrained.pth`; `lavis/models/blip2_models/blip2.py:Blip2Base.init_tokenizer()` requires `/root/bert-base-uncased`; correction dictionaries and cache PKLs as above. `workbench/registry/auxiliary_assets.yaml` contains no ConeSep entries.

## HABIT

### Source and official path

- Official FashionIQ entry: `datasets.py:FashionIQ.__init__`; constructor defaults `split='original-split'`, and uses string-concatenated `path + 'resized_image'`, `path + 'image_splits'`, `path + 'captions'` paths (trailing separator needed). `get_test_data(category)` reads `captions/cap.{category}.val.json`, `captions/correction_dict_{category}.json`, and `image_splits/split.{category}.val.json`; query order follows caption annotations and gallery order follows split file.

README's FashionIQ preparation section specifies downloaded FashionIQ files under the `resized_image` layout and correction dictionaries; no upstream resize/conversion function was found in HABIT root. First initialization writes `fashion_iq_data.json` plus all category query/target PKLs; later initialization trusts those caches (`datasets.py:FashionIQ.__init__`). Workbench's iLearn layout validator does not require the PKLs or check cache staleness.

### Text, image and noise handling

- `FashionIQ.correct_text()` (`datasets.py`) lowercases raw captions, maps every ASCII `string.punctuation` char to a space, whitespace-splits, exact-token correction-dictionary substitution, and joins tokens with spaces. `concat_text()` preserves original caption order and joins the two with ` and `. `get_test_data()` applies this to val query captions. Correction dictionaries are external dataset inputs; pinned source does not establish who generated them.
- `test.py:test()` then applies its own `txt_processors['eval']`. `lavis/processors/blip_processors.py:BlipCaptionProcessor.pre_caption()` lowercases and replaces only `[.!"()*#:;~]`, collapses repeated whitespace, strips and truncates at 50 words. `lavis/models/blip2_models/blip2.py:Blip2Base.init_tokenizer()` loads `BertTokenizer` from absolute `/root/bert-base-uncased` and adds `[DEC]`. `lavis/models/blip2_models/HABIT.py:HABIT.extract_retrieval_compose()` tokenizes with fixed max-length padding/truncation (`max_txt_len`, default 32). Thus dataset correction and eval processor/tokenizer are separate stages.
- `train.py:load_dataset()` selects `targetpad_transform(1.25,224)` and passes it to `FashionIQ`; query reference/gallery image getters open JPG, RGB-convert and apply it (`datasets.py:get_test_img`). `data_utils.py:TargetPad.__call__()` symmetrically zero-pads short dimension for aspect ratios ≥1.25; `targetpad_transform()` then does bicubic `Resize(224)`, `CenterCrop(224)`, RGB, `ToTensor`, CLIP mean `(0.48145466,0.4578275,0.40821073)` / std `(0.26862954,0.26130258,0.27577711)`. Training also selects targetpad, not squarepad.
- `FashionIQ.shuffle()` in `datasets.py` mutates randomly sampled training `fashioniq_data` candidate/caption/target assignments. `train.py:load_dataset()` calls it for the train set; `test.py:test()` does not. Validation query/target lists are constructed separately and are unaffected. Evaluation must not invoke train-data noise injection.

### Native evaluation, checkpoint routing, assets

- Callable native evaluator: `test.py:test(params,model,testset,category,txt_processors)`. It sets `model.eval()`, encodes `source_img_data` + `mod.str` with `HABIT.extract_retrieval_compose()`, obtains target-gallery embeddings via `extract_retrieval_target()`, scores with `np.matmul(all_queries,all_imgs)`, squeezes and takes `max(-1)` across target feature tokens. `test.py` sets each reference's gallery score to `-10e10` before descending ranking; R@1/R@10/R@50 are percentage hits. No standalone FashionIQ CLI, checkpoint loader, or main block is present in this evaluator; `train.py` invokes it during training.
- `datasets.py:FashionIQ.get_test_data()` has an `original-split` branch that includes every validation split image in source order. The reference exclusion in `test.py:test()` is explicit and occurs only after score computation, before recall. This is full-gallery/reference-excluded protocol and differs from both reference-eligible `fashioniq_original_split` and endpoint-only `fashioniq_val_split`.
