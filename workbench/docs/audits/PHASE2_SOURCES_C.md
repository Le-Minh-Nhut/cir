# Phase 2 upstream-source comparison: HINT, INTENT, SPRC

Static audit of the pinned executable sources and current workbench contracts. No checkpoint, dataset, runtime environment, or inference was exercised. `MATCH` below applies only to the named behavior, not to end-to-end model, score, or reproduction equivalence. No `EXACT_MATCH` is claimed.

## Findings at a glance

| Method | Source-native validation gallery | Reference handling | Registered workbench protocol | Standalone source evaluation-only CLI |
| --- | --- | --- | --- | --- |
| HINT | Ordered pair-union of validation annotation references then targets; `datasets.py:FashionIQ.get_test_data` | Similarity set to `-10e10` before descending rank | `fashioniq_val_split` | **No.** `test.py:test` is callable only; `train.py` trains and evaluates its in-memory model |
| INTENT | Full ordered validation split by default (`original-split`); pair-union only with `val-split`; `datasets.py:FashionIQ.get_test_data` | Source score set to `-10e10` before descending rank | `fashioniq_full_gallery_ref_excluded` | **No.** `test.py:test` is callable only; `train_INTENT.py` trains and evaluates its in-memory model |
| SPRC | Full ordered validation split; `src/data_utils.py:FashionIQDataset` classic mode | Reference remains in gallery and is not masked; `inference` receives but does not use reference features | `fashioniq_original_split` | **Yes, structurally.** `src/blip_validate.py` CLI calls FashionIQ evaluator, but its default model name is not registered; checkpoint mapping is unresolved |

**Gallery question settled:** HINT is the only one of these three whose pinned FashionIQ validation dataset constructs the pair-union gallery. INTENT constructs pair-union only when `split == 'val-split'`, but official `train_INTENT.py` defaults to `original-split`, so its native/default path uses the full gallery. SPRC uses full gallery. Neither INTENT's default nor SPRC builds pair-union.

## HINT

**Pinned source:** [`iLearn-Lab/ICASSP26-HINT@bec50b6c8c19111893b617979502b948d1cea5b2`](https://github.com/iLearn-Lab/ICASSP26-HINT/tree/bec50b6c8c19111893b617979502b948d1cea5b2).

- **Official dataset entrypoint:** `datasets.py:FashionIQ.__init__` sets `<path>resized_image`, `image_splits`, and `captions`; `datasets.py:FashionIQ.get_test_data` reads `split.{category}.val.json`, `cap.{category}.val.json`, and `correction_dict_{category}.json`. `datasets.py:FashionIQ.get_img` / `get_test_img` open `resized_image/{category}/{id}.jpg` as RGB and apply the passed transform. `train.py:load_dataset` selects this class for `--dataset fashioniq`; `train.py:train_and_evaluate` calls `test.test` separately for `dress`, `shirt`, and `toptee`.
- **Official preparation functions:** no source image-resize/preparation script or FashionIQ eval-only preparation CLI found in this checkout. Dataset construction itself does generate `fashion_iq_data.json` and six query/target pickle caches when the JSON cache is absent (`datasets.py:FashionIQ.__init__`, `train_init_process`, `get_test_data`, `save_obj`). The fresh-cache path also reads all three `cap.{category}.train.json` files in `train_init_process`; the cache-present branch loads pickles instead and does not rebuild them. `README.md` documents a manually downloaded FashionIQ tree; it does not provide a resize generator. Source code's actual image paths require the category-local `resized_image` layout.
- **Official text preprocessing:** `datasets.py:FashionIQ.correct_text` lowercases each raw caption, translates every `string.punctuation` character to a space, strips/splits on whitespace, applies exact token lookup in category correction dictionary, and rejoins with single spaces. `concat_text` preserves caption 0 then caption 1 and joins with literal `" and "`; `get_test_data` applies this to each raw validation pair. `test.py:test` runs each composed string through `txt_processors["eval"]`. LAVIS `configs/models/blip2/blip2_pretrain.yaml` selects `blip_caption`; `lavis/processors/blip_processors.py:BlipCaptionProcessor.pre_caption` lowercases again, replaces `[.!"()*#:;~]` with spaces, collapses repeated whitespace, trims, and truncates to 50 words (empty prompt by default). `lavis/models/blip2_models/HINT.py:HINT.extract_retrieval_compose` then tokenizes with the model tokenizer, max length 32, padding/truncation. There is no prompt template beyond the literal ordered-caption `and` and the processor's empty default prompt.
- **Official image preprocessing:** `train.py:load_dataset` hardcodes `targetpad`, ratio `1.25`, size `224`, calling `data_utils.py:targetpad_transform`. This custom source helper uses the repository's `torchvision.transforms` `Compose`, `Resize`, `CenterCrop`, `ToTensor`, and `Normalize`, plus `TargetPad` and `_convert_image_to_rgb`: pad shorter dimension with zero when aspect ratio is at least 1.25; bicubic resize with integer short-side size 224; center-crop 224; convert RGB; tensor; CLIP mean `(0.48145466, 0.4578275, 0.40821073)` and std `(0.26862954, 0.26130258, 0.27577711)`. `datasets.py:get_test_img` invokes this transform. `load_model_and_preprocess` returns a LAVIS visual processor in `train.py:create_model_and_optimizer`, but FashionIQ dataset uses the custom transform, not that returned visual processor.
- **Native evaluation protocol:** `test.py:test(params, model, testset, category, txt_processors)` chooses the category's prebuilt query/target lists; query features come from `HINT.extract_retrieval_compose` and target multivectors from `HINT.extract_retrieval_target`. It computes matrix products, takes max over target feature-token dimension, sets each source/reference candidate score to `-10e10`, then descending `np.argsort`; target hit is tested for R@1, R@10, R@50 and returned as percent. `train.py:train_and_evaluate` records each category's metrics and selects a best epoch using the **sum of three category R@10s** (`t[1][1]`); it does not emit a native arithmetic-mean R@10/R@50 aggregate. HINT query composition uses both reference image and text inside `HINT.extract_retrieval_compose`'s Q-former conditioning.
- **Gallery construction:** `datasets.py:FashionIQ.get_test_data` preserves validation annotation order. For each query it takes `candidate` as `source_img_id` and `target` as `target_img_id` by lookup in the full split array, then appends source followed by target to `test_targets_id` only if unseen. This is the first-seen ordered pair-union; it does not retain all split IDs. The reference is present in that union, then masked in `test.py:test` before ranking. This confirms native `fashioniq_val_split`, not full gallery.
- **Checkpoint routing:** `train.py:create_model_and_optimizer` initializes `load_model_and_preprocess(name="HINT", model_type="pretrain", is_eval=False, ...)`. `HINT.PRETRAINED_MODEL_CONFIG_DICT` routes `pretrain` to `blip2_pretrain.yaml`; `HINT.from_config` calls `load_checkpoint_from_config`. The launcher defines `--restore_file`, but no use of it exists in the training path; it does not load the downloaded `fashioniq.pt` for validation. `train.py:train_and_evaluate` evaluates the in-memory model and saves whole models with `torch.save`. `test.py` accepts an already-constructed model and has no checkpoint argument/loader.
- **Auxiliary assets:** base BLIP-2 weights are declared by the LAVIS config URL `https://storage.googleapis.com/sfr-vision-language-research/LAVIS/models/BLIP2/blip2_pretrained.pth`; the HINT FashionIQ model weight is separately listed in workbench `models.yaml` as `fashioniq.pt` at the official Hugging Face URL. Three correction dictionaries are mandatory source inputs (`captions/correction_dict_{dress,shirt,toptee}.json`); they are not bundled/pinned by this upstream source. Workbench `auxiliary_assets.yaml` has no HINT records, and its `preparation_contracts.yaml` has no HINT-specific contract entry.
- **Current workbench implementation:** `models.yaml` registers `native_protocol: fashioniq_val_split`, layout `fashioniq_ilearn_resized`, and `manual_ilearn_resized`; `fashioniq_layout.py:ilearn_resized_paths` checks validation captions, split files, category image directories and correction dictionaries. It does not check train captions or generated HINT pickle caches. `preparation_contract_for_model` in `backend/registry.py` requires `preparation_id`; HINT has none, so `scripts/prepare_model.py:status` falls back to `standard_paths`, despite the model's `fashioniq_layout`. Strict runtime path preflight uses the layout helper. `HintAdapter` only names `test.py`; inherited `OfficialScriptAdapter.command` raises `NotImplementedError` and does not pass dataset root, checkpoint, or model construction arguments. Local `src/evaluation/fashioniq.py:build_val_gallery` and `src/datasets/fashioniq.py:build_pair_union_gallery` build the same reference-then-target ordered union. `src/evaluation/fashioniq_encoder.py:fashioniq_encoder_recall_at_k` removes the reference after stable descending sort; generic `src/evaluation/fashioniq.py:recall_at_k` has no reference argument and does not remove it. The registered protocol definitions are in `workbench/registry/models.yaml`; `conf/protocol/` is empty.

## INTENT

**Pinned source:** [`iLearn-Lab/AAAI26-INTENT@2a75fc6f57d1a036bf3167a7fe1d2cee072f51f3`](https://github.com/iLearn-Lab/AAAI26-INTENT/tree/2a75fc6f57d1a036bf3167a7fe1d2cee072f51f3).

- **Official dataset entrypoint:** `datasets.py:FashionIQ.__init__(path, category=None, transform=None, noise_ratio=0, split='original-split')` sets the same category-resized paths, caption directory, and split directory as HINT. `datasets.py:FashionIQ.get_test_data` reads each category's validation split and annotation JSON, builds query records in annotation order, and chooses gallery according to `self.split`. `train_INTENT.py:load_dataset` passes CLI `args.split` (default `original-split`) and `args.fashioniq_path`; `train_INTENT.py:train_and_evaluate` selects `dress`, `shirt`, `toptee` separately and calls `test.test`.
- **Official preparation functions:** no source image-resize generator or standalone FashionIQ prep CLI found. `datasets.py:FashionIQ.__init__` / `train_init_process` / `get_test_data` create the same JSON and query/target pickle caches as HINT when `fashion_iq_data.json` is absent. The cache-fresh path reads each category's train annotations and correction dictionary; cache-present path trusts existing files. `train_INTENT.py:load_dataset` invokes `trainset.shuffle()` after construction; the default noise ratio is 0. The actual source path `resized_image/{category}/{id}.jpg` is required; the source README does not supply a resize implementation.
- **Official text preprocessing:** `datasets.py:correct_text` and `concat_text` use lowercasing, all-`string.punctuation`-to-space translation, whitespace tokenization, exact dictionary token substitution, and source-order `caption0 + " and " + caption1`. `test.py:test` applies `txt_processors["eval"]`; the local pinned `lavis/processors/blip_processors.py:BlipCaptionProcessor.pre_caption` applies lowercasing, replaces `[.!"()*#:;~]`, collapses/strips whitespace, truncates at 50 words, and adds the empty default prompt. `Blip2QformerCir.extract_retrieval_compose` tokenizes to max length 32. No other prompt template is applied at FashionIQ query construction.
- **Official image preprocessing:** `train_INTENT.py:load_dataset` hardcodes `targetpad_transform(1.25, 224)` from `data_utils.py`; this is a custom torchvision `Compose`: custom zero `TargetPad`, torchvision `Resize(224, interpolation=PIL.Image.BICUBIC)`, `CenterCrop(224)`, RGB conversion, `ToTensor`, CLIP normalization means `(0.48145466, 0.4578275, 0.40821073)` / std `(0.26862954, 0.26130258, 0.27577711)`. `datasets.py:get_test_img` applies it to RGB JPGs. Returned LAVIS visual processors are not used by this FashionIQ dataset path.
- **Native evaluation protocol:** default launcher `args.split == 'original-split'`; `datasets.py:FashionIQ.get_test_data` enumerates full validation split candidates as `test_targets` in original order. `test.py:test` builds query/target features with `Blip2QformerCir.extract_retrieval_compose` and `extract_retrieval_target`, takes max-over-target-token similarity, sets the reference score to `-10e10` before descending sort, and reports percent R@1/R@10/R@50. Metrics are generated per category. `train_INTENT.py:train_and_evaluate` chooses best epoch by the sum of each category's R@10 (`t[1][1]`) and writes per-category values; no macro R@10/R@50 result is formed there. `Blip2QformerCir.extract_retrieval_compose` conditions on both reference image and text.
- **Gallery construction:** `datasets.py:FashionIQ.get_test_data` always makes query IDs by `images.index(candidate/target)`. With default `original-split`, it enumerates every validation split ID, preserving full split order; this is full gallery, not pair-union. `test.py:test` masks each source candidate by its position in full `test_targets_id` before ranking, so the default is `fashioniq_full_gallery_ref_excluded`. The same method's optional `val-split` branch creates a first-seen, source-then-target pair-union, but the official launcher does not select that branch by default.
- **Checkpoint routing:** `train_INTENT.py:create_model_and_optimizer` calls `load_model_and_preprocess(name="Blip2QformerCir", model_type="pretrain", ...)`; `Blip2QformerCir.PRETRAINED_MODEL_CONFIG_DICT` selects LAVIS `blip2_pretrain.yaml` and `from_config` loads that configured base checkpoint. The FashionIQ `test.py:test` accepts a constructed model only. The training launcher saves the whole in-memory model with `torch.save`; it has no FashionIQ evaluation checkpoint load path. Workbench lists author Hugging Face `intent_fiq_0.2.pt`, `.0.5.pt`, `.0.8.pt`; metadata identifies noisy-training variants and clean evaluation, but no standalone source evaluator routes them.
- **Auxiliary assets:** the configured LAVIS base BLIP-2 checkpoint is `https://storage.googleapis.com/sfr-vision-language-research/LAVIS/models/BLIP2/blip2_pretrained.pth`; each category correction dictionary is a required manual source dataset input and is not pinned in this source tree. Workbench `auxiliary_assets.yaml` has no INTENT asset rows; `preparation_contracts.yaml` has no INTENT-specific entry.
- **Current workbench implementation:** `models.yaml` declares `fashioniq_full_gallery_ref_excluded`, literature `original`, `fashioniq_ilearn_resized`, and `manual_ilearn_resized`. `fashioniq_layout.py:ilearn_resized_paths` checks the val inputs and category directories but not train annotations/caches required by a fresh source `FashionIQ` constructor. INTENT has no `preparation_id`; thus `prepare_model.py:status` follows the standard-layout fallback rather than a registered iLearn contract, while strict runtime path checks use the layout helper. `IntentAdapter` names `test.py` only and inherits the unimplemented `OfficialScriptAdapter.command`; it cannot supply split, dataset path, model setup, or checkpoint. Local `src/evaluation/fashioniq.py:build_original_gallery` returns the full split order and `build_val_gallery` returns pair-union, but `build_fashioniq_gallery` has no full-gallery-reference-excluded option and `recall_at_k` has no reference exclusion. `src/evaluation/fashioniq_encoder.py` implements only pair-union and post-sort reference removal. Protocol registry is `workbench/registry/models.yaml`; no YAML files exist under `conf/protocol/`.

## SPRC

**Pinned source:** [`chunmeifeng/SPRC@2935a5397732260d1db6fa577e5926f963e36f0f`](https://github.com/chunmeifeng/SPRC/tree/2935a5397732260d1db6fa577e5926f963e36f0f).

- **Official dataset entrypoint:** `src/data_utils.py:FashionIQDataset.__init__(split, dress_types, mode, preprocess)` loads `fashionIQ_dataset/captions/cap.{category}.{split}.json` and `fashionIQ_dataset/image_splits/split.{category}.{split}.json` under fixed `base_path` (SPRC source root). `FashionIQDataset.__getitem__` returns annotation-order reference/target/caption tuples in relative validation mode and ordered `image_names` plus transformed images in classic mode. Images are fixed at `fashionIQ_dataset/images/{id}.png` (no category subdirectory). `src/blip_validate.py:clip_finetune_fiq` selects categories in order `dress`, `toptee`, `shirt` and builds one relative and one classic validation dataset per category.
- **Official preparation functions:** no FashionIQ resize/preparation function or standalone data-preparation CLI found. `FashionIQDataset` reads raw PNG images plus annotation/split JSON directly. - **Official text preprocessing:** `src/validate_blip.py:generate_fiq_val_predictions` takes each original caption pair in order, strips edge characters from the set `.?, `, capitalizes caption 0, joins with literal `" and "`, then appends stripped caption 1. No correction dictionary is loaded by `FashionIQDataset` or evaluator. `txt_processors["eval"]` is LAVIS `blip_caption` from `blip2_pretrain.yaml`: empty prompt, lowercase; replace `[.!"()*#:;~]` with spaces; collapse whitespace; trim; max 50 words (`src/lavis/processors/blip_processors.py:BlipCaptionProcessor.pre_caption`). `Blip2QformerCirRerank.inference` then tokenizes to max length 32.
