# Automated data preparation

What the workbench prepares by itself, what it refuses to invent, and the exact rule that decides
which is which.

## The rule

A step runs automatically only when the pinned source establishes all three of:

1. **the file** -- a path some evaluator actually opens,
2. **the recipe** -- an author-published tool, script or documented command that produces it,
3. **the inputs** -- files that are already present.

If (2) is missing, the step is not automated and the model is blocked with the file named. If (3) is
missing, the step fails and says which input is absent. The workbench never substitutes a plausible
artifact for an author artifact: a caption set generated by a different model, a checkpoint from a
different variant, or a resized layout from a different tool all change the experiment.

## What runs automatically today

| Step | Contract marker | Source evidence | Output |
|---|---|---|---|
| Canonical dataset link | `canonical_dataset_link` in the registry | `src/data_utils.py` derives its data root from its own file location | `<checkout>/fashionIQ_dataset -> <dataset_root>` symlink |
| Source-shipped correction dictionaries | `generator: pinned_source_file` | the evaluator reads `<dataset>/captions/correction_dict_<cat>.json`; the author ships `correct_files/correction_dict_<cat>.json` | byte-identical copy into the dataset |
| Per-category resized images | `generator: fashioniq_resize_images` | the model README documents `start_kit/resize_images.py` at 256px and the output directory; the evaluator opens `resized_image/<cat>/<id>.jpg` | resized JPEGs, derived from the canonical images |
| Official auxiliary downloads | `workbench/registry/auxiliary_assets.yaml` | the pinned code reads the file; the author publishes it | downloaded, hashed, atomically published |

Every one of these is executed by `workbench/scripts/prepare_model.py --execute --allow-preparation`,
which is the step Autopilot's `preparation` stage invokes. There is no separate manual stage list to
run: one command covers all of them.

### Details that matter

**Correction dictionaries.** The copy is byte-for-byte and refuses to overwrite a destination whose
contents differ. Both halves are checked, because a dictionary that "looks like a dictionary" is not
the author's dictionary. The pins are recorded in `workbench/registry/preparation_contracts.yaml`.

**Resized images.** The FashionIQ tool writes a flat directory at its documented default size; the
iLearn-family readers open `resized_image/<category>/<id>.jpg`, and DCNet opens a flat
`resized_images/<id>.jpg` at `[256, 256]` from its own documented script. The recipe therefore
applies the documented transform and writes the layout the evaluator reads, which the contract
declares per model. Existing files are never overwritten, and the canonical `images/` directory is
only ever read.

**Auxiliary downloads.** Only registry entries with `automatic_download_available: true` are
fetched, each from a pinned author revision, verified against the published SHA-256 and size where
one is recorded, written to a temporary file and published atomically. A mismatch refuses the
download and leaves nothing behind.

## What is deliberately not automated

| Model | Asset | Why it is blocked |
|---|---|---|
| csmcir | `COT_ours2/fashioniq/<cat>_cot_val.json` | read by `src/utils_csmcir.py:100`; the author publishes no file, URL or checksum anywhere in the repository or the author Hugging Face repo |
| encoder | `datasets1.py` | imported at `evaluate_model.py:7`; the module is absent from the pinned checkout |
| pair | `MHTransformer_rev.py` | imported at `models/model.py:13`; the module is absent from the pinned checkout |
| dcnet | `captions/cap.<cat>.glove.val.pkl` | the generator samples unseeded random OOV vectors; regenerating produces a different artifact, so the author artifact is required |
| clvc_net, dcnet, sprc | the author checkpoint archives | published through author Drive folders with no per-file mapping or checksum |

These are reported as `BLOCKED_EXTERNAL_ASSET`-family blockers. Each names the exact path, the source
line that reads it, and the operator action that would unblock it. None of them is replaced by an
approximation.

## Verifying a preparation run

```bash
# Execute the automated preparation for one model (the mode is `prepare`; run.sh forwards to
# pipeline.py, which requires a mode from {mock,prepare,real,serve,status,setup,reproduce,analyze,
# all,report}).
./workbench/run.sh prepare --model limn --dataset-root <dataset> --apply --allow-preparation

# Read-only preparation status, straight from the script.
python3 workbench/scripts/prepare_model.py --model limn --dataset-root <dataset>
```

Real regressions for the two automated generation steps live in
`workbench/tests/test_prepare_dataset.py`: one proves the resized layout and size the evaluator
reads, one proves a source-shipped dictionary is staged byte-identically, one proves a re-run leaves
operator files alone, and one proves `--dry-run` writes nothing.
